# Магазин электроники — инструкция

## Что установить
1. Windows 10/11 x64, Visual Studio 2026 (18.0 или новее) с поддержкой .NET 10, компонентом разработки классических приложений .NET и .NET 10 SDK. Можно запускать через терминал без Visual Studio.
2. SQL Server 2025 Developer или Express, служба Database Engine. Добавьте текущего пользователя Windows в администраторы локального учебного экземпляра.
3. SQL Server Management Studio (SSMS). Расширение Avalonia для Visual Studio удобно для XAML, но не обязательно для запуска.
4. Для первого восстановления NuGet-пакетов нужен интернет. Фиксированные зависимости: Avalonia 12.0.0, Microsoft.Data.SqlClient 6.1.3.

## Первый запуск по шагам
1. Распакуйте весь архив в обычную папку, например C:\Projects\ElectronicsStore. Не открывайте решение прямо из ZIP.
2. Запустите SSMS и подключитесь к своей службе SQL Server через Windows Authentication. Запомните имя сервера в окне подключения. Часто это .\SQLEXPRESS, localhost либо (localdb)\MSSQLLocalDB.
3. Откройте Database/ElectronicsStore.sql. В меню Query включите SQLCMD Mode. Нажмите Execute (F5). Скрипт создает НОВУЮ базу ElectronicsStore и не удаляет существующую. При повторном запуске он остановится: это защита от перезаписи ваших данных.
4. Внизу проверьте числа: Roles 4; Categories 4; Manufacturers 4; Suppliers 2; Clients 4; Products 8; Orders 1; OrderItems 1. DBCC не должен вывести нарушения ограничений. Это ожидаемые числа для свежей базы.
5. В папке ElectronicsStore откройте connection.txt Блокнотом. Вместо .\SQLEXPRESS впишите ТОЧНО имя сервера из SSMS. Обратный слеш один. Сохраните. Database=ElectronicsStore оставьте. Integrated Security=True использует учетную запись Windows, не логины из приложения. TrustServerCertificate=True допустим для локального учебного сервера.
6. Откройте ElectronicsStore.sln в Visual Studio. Дождитесь восстановления NuGet. Выберите ElectronicsStore запускаемым проектом. Нажмите Ctrl+F5. Альтернатива: дважды нажмите START.cmd.
7. Введите логин из таблицы ниже и пароль Store2026! либо нажмите «Войти как гость».

|Логин|Роль|
|---|---|
|admin@store.local|Администратор|
|manager@store.local|Менеджер|
|seller@store.local|Продавец|
|client@store.local|Клиент|

Пароль всех четырех учебных учетных записей: **Store2026!**. В базе хранится PBKDF2-SHA256 с солью, а не открытый пароль. Перед реальным применением смените учебные пароли.

## Как работать
Гость просматривает каталог, ищет по названию/коду, выбирает категорию и сортировку. После входа можно открыть «Подробнее», указать целое количество и скидку 0–30%, добавить товар в корзину. В корзине проверьте состав. Сотрудник выбирает покупателя; клиент оформляет только на себя. Кнопка подтверждения сохраняет заказ и уменьшает остаток в одной транзакции. Повторяющийся товар сначала уберите из корзины, затем добавьте с новым количеством. При изменении цены очистите корзину и заново выберите товар.

«Заказы» показывает собственные заказы клиенту и все заказы сотруднику. Укажите номер и откройте состав. Менеджер и администратор могут отменить заказ: остатки возвращаются, история сохраняется, повторная отмена не возвращает товар повторно. Физическое удаление продаж не реализовано, чтобы сохранить учет.

Менеджер и администратор: «Товары» добавляет товар, «Изменить» в каталоге редактирует выбранный. Можно удалить только товар без продаж. «Справочники» позволяет добавлять и изменять категории, производителей и поставщиков. «Отчёт» считает количество и выручку по оформленным заказам за включительный диапазон дат.

Администратор: «Пользователи» — код 0 для новой записи; для изменения введите код и нажмите «Загрузить по коду». Заполните данные, выберите роль, установите активность и сохраните. Пустой пароль при изменении сохраняет прежний. Текущую учетную запись изменять нельзя: войдите другим администратором. Учетные записи отключаются флажком, а не удаляются вместе с историей.

## Проверка и перенос
CHECK.cmd собирает решение и запускает 12 независимых расчетных проверок. Сценарии БД и UI описаны в docs/TEST_PLAN.md. Они требуют запущенного SQL Server. В данной среде разработки нет SDK .NET и SQL Server, поэтому фактический запуск C# и интеграционные проверки здесь не выполнены. Не считайте приложенный план протоколом успешного испытания.

PUBLISH.cmd создает publish с автономной Windows x64 версией. Скопируйте всю папку publish; на втором компьютере подготовьте SQL Server и измените publish/connection.txt. При работе через сеть укажите имя сервера; разрешите TCP/IP SQL Server и доступ Windows-пользователю к базе. Ролевые проверки находятся в сервисах приложения. Подключение к серверу использует Windows-права, поэтому это учебная доверенная локальная сеть; для недоверенных клиентов нужен отдельный сервер API.

## Если появилась ошибка
- «Ошибка сборки»: откройте View → Error List и Output → Build, проверьте установленный .NET 10 SDK командой dotnet --list-sdks, восстановите пакеты. Не запускайте устаревшую сборку.
- «Сервер не найден»: проверьте имя экземпляра и запуск службы SQL Server. connection.txt редактируется рядом с запускаемым exe; после изменения исходного файла пересоберите проект.
- «Cannot open database»: сначала выполните SQL-файл в SSMS на том же сервере.
- Ошибка сертификата: для локального сервера в строке уже есть TrustServerCertificate=True.
- Ошибка UNIQUE: такая почта или название справочника уже существует.

## Контроль версий
Архив содержит исходные файлы и .gitignore. Для публикации в своем репозитории: git init, git add ., git commit -m "Initial electronics store project". Затем создайте пустой репозиторий в своей учетной записи и выполните команды подключения remote из его страницы. Публичный репозиторий автоматически не создавался. Укажите его реальную ссылку в записке после публикации.
